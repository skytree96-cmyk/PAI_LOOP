# Latest PPS manifest remains authoritative when malformed

A newest PPS metadata row with a missing, null, or non-list attachment manifest used to be skipped by current-source selectors. Readers could therefore reuse an older manifest, expose its accepted attachment counts, or select its quantitative profile. A later extraction/materialisation row also exposed the same fallback in the write guard.

Current-source selection now picks the newest PPS metadata kind before checking its manifest shape. A malformed current container yields incomplete coverage, no reusable attempts, zero known current slots, no quantitative executable rules, and no enrichment work. It never falls back to an older list. The write guard returns false and internal failure reporting appends no marker against the replaced source. Stored versions and earlier analyses remain unchanged. Empty/invalid-entry lists retain existing incomplete behavior; valid current lists and legacy non-PPS sources retain their prior behavior.

This corrects a reproducible synthetic source-boundary defect. Its prevalence in production has not been measured, and it does not by itself explain the current live REVIEW distribution. Normal PPS ingestion already creates list manifests. General version imports or legacy malformed rows can still reach the reader boundary, so validation is required at reads as well as writes.

Quantitative scoring is not gated on the Busan title or notice number. The generic dynamic route runs before the historical named-profile fallback. Four synthetic title/key/notice-number/agency substitutions preserved the entire dynamic result, and a separate fixture with renamed attachment labels/manifest identities also passed after rebuilding all source bindings. Source-format repairs introduced for a Busan HWP example apply by exact source structure; they do not restrict the generic route to that notice. Rules without a table, unresolved source conflicts, unsupported rule dimensions, and missing verified company inputs remain distinct reasons for not producing a score.

Validation: 34 added focused cases cover malformed latest containers (including missing fields), a later materialisation, read/history/retry/source gates, database write guards, no-provider enrichment, no failure-marker mutation, normal current data, legacy no-PPS behavior, and empty/invalid/stale list forms. Related existing regression results are recorded in the integration handoff. Pipeline auto-selection/basis callers require the same newest-kind-first invariant and are being integrated in a separate coordinated patch.
