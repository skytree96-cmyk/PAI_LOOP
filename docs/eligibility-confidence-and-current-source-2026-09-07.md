# Eligibility confidence and authoritative current source

A current, mechanically accepted PPS extraction could still yield R07 for a strong mandatory qualification clause when an unrelated optional clause lowered the document mean or the materialized document minimum. In a synthetic current-contract example, the qualification anchor was 0.98 and an optional proposal-format anchor was 0.72. The source was technically complete and had no missing marker, but qualification was REVIEW. Adding an unrelated non-eligibility gap activated the older partial gate and changed that same qualification to PASS. The presence of a gap must not determine the outcome of the separately proved condition.

The pipeline now allows a narrow per-requirement evidence path when all current PPS attachments are strictly accepted and technically complete, the selected source IDs exactly match the current manifest attempts, and no missing/unreadable source or other source-validation warning remains. Every mandatory eligibility clause must independently satisfy the existing 0.90 anchor threshold. A required action is included only with its own verified anchor. Company facts still require the existing evidence and deadline checks and may produce FAIL or REVIEW. Weak mandatory qualification evidence, absent anchors, foreign attachment identity, invalid record fingerprints, mismatched document digests, incomplete files, and unknown or eligibility-related gaps retain R07.

The original extraction payloads, confidence values, document status, source bindings and quantitative rules are unchanged. Low confidence remains visible on its actual source and through document-risk reporting. Normal high-confidence success receives no new gate warning. The new audit warning is PER_REQUIREMENT_CONFIDENCE_GATE_APPLIED. The existing non-eligibility-gap pathway and its reviewable-anchor threshold remain unchanged.

The automatic source selector also treats the newest PPS metadata row as authoritative even when its attachment_manifest is missing, null, an object or a string. These malformed values produce an invalid, empty current manifest basis; automatic analysis cannot fall back to an older valid manifest. Explicit source_version_ids still permit selecting the requested historical audit source, but the malformed current manifest does not become complete.

PIPELINE_VERSION changes from analysis-pipeline-0.6.4 to analysis-pipeline-0.6.5. The pipeline version participates in the analysis input fingerprint, so the first recalculation creates a new immutable run instead of reusing the old R07 result; identical subsequent calculations reuse that new run. Extraction prompt 0.5.5, schema 0.4.1, validator 0.6.18 and quantitative engine 1.7.3 are unchanged. A pipeline recalculation invokes no provider and requires no extraction replay. Already completed queue items still need an explicitly requested provider-free recalculation; changing the pipeline does not rewrite a terminal job or its historical evaluation.

Validation uses synthetic local HWPX transport, the actual current extraction schema/anchor validator, persisted manifest-bound records and the real pipeline. It covers both a low document mean and a mean above 0.90 with a low unrelated minimum, the exact 0.90 threshold, weak mandatory clauses, company FAIL/missing data, source integrity failures, actual missing content, versioned old-run replacement with no new provider calls, and malformed latest-manifest values with historical audit selection retained. No production data or operations were used.

Validation result: 26 new synthetic cases passed and were independently re-run by case_contract_compatibility. The broader pipeline/evaluator/policy/API/extraction-contract/daily set contains 304 cases: 303 passed on the first run and one failed because the isolated fixture copy lacked the unchanged workflows directory; that same case passed after copying the missing repository fixture. No runtime change was made for that environment correction. compileall for src/tests passed. A combined full gate and production deployment remain the parent task’s responsibility.
