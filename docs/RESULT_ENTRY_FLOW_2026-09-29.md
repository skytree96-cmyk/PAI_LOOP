# 결과 입력 흐름 (2026-09-29)

`/result-entry`와 기존 결과 누락 목록에서 공고 제목, 행/카드, 결과 입력 버튼을 선택하면 해당 공고의 결과 편집창을 바로 연다. 별도 **공고 상세** 버튼은 기존 상세 화면을 연다. 키보드 Enter/Space도 같은 동작이다.

**저장하고 상세 보기**는 서버가 반환한 저장 결과를 상세의 **입찰 결과** 탭에 표시한다. 목록 갱신으로 탭을 초기화하지 않는다. 상세에서 **결과 수정**, **결과 입력 목록으로**를 사용할 수 있다.

**임시저장**은 작성 중(DRAFT)으로 저장하며 목록에 **작성 중 / 이어서 입력**으로 남는다. 확인 완료(VALIDATED)된 최종 결과(WON, LOST, NO_BID, CANCELLED)만 결과 입력 대상에서 제외한다. 제출(SUBMITTED)은 아직 최종 결과가 아니다. 보관(ARCHIVED)은 미입력 취급한다. 기존 출처 및 결과별 필수값 검증을 유지한다.

조회 부서의 최신 revision이 우선하며, 다른 부서의 완료 기록으로 내 부서의 입력 대상을 숨기지 않는다. 해당 부서 기록이 없는 경우 공통 provider 기록의 기존 검증 기준을 따른다. API의 `has_bid_outcome`은 기록 존재 여부를 유지하고 `result_entry_status`가 MISSING/DRAFT/COMPLETE를 전달한다. 대시보드 집계, 공고 목록, 상세 조회가 같은 기준을 사용한다.

검증은 합성 공고/계정과 로컬 DB로 수행한다. 운영 데이터에 검증용 결과를 입력하지 않는다. 회귀 테스트는 직접 진입, 저장 응답 표시, 임시저장, 부서 분리, 오래된 비동기 응답 무시, 목록 갱신 후 탭 유지와 API 집계 일치를 포함한다.
