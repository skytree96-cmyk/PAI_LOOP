# Explicit accepted source-gap recovery

An extraction can be ACCEPTED while its quantitative validation remains INCOMPLETE. Previously an explicit reviewed campaign retried such an attachment only when it contained review candidates. A document reporting a blocking source gap but no candidate was therefore reused without a fresh extraction.

The retry guard now also accepts a valid REVIEW/INCOMPLETE record containing EXTRACTION_DECLARED_INCOMPLETE and a schema-valid original payload with a nonempty, non-benign gap. Whitespace and Unicode format-only strings are not gaps. Exact manifest/document/contract/fingerprint validation still precedes retry selection. Ordinary reads preserve accepted output. Only the explicitly frozen pre-request IDs may be superseded, and their version boundary prevents new outcomes from being retried or deduplicated into pre-request history during continuation.

The shared source-gap policy additionally recognises a complete statement naming the absent original RFP and explicitly identifying its quantitative technical-score table. It returns a required RFP sibling role; it does not claim that the missing table exists. The existing aggregate proof still requires a different current attachment, an unambiguous RFP source label, valid source bindings, and an AVAILABLE table. Missing/incomplete sources, form documents, self-supply, qualitative/eligibility/legal or compound omissions stay blocked. Price-formula omissions are unchanged.

Local-absence-only records remain excluded from this new retry rule because a current sibling may already resolve them. Determining which local-only records remain unresolved needs whole-notice aggregate context and is outside this change. This boundary prevents charging for a normal reference-only notice merely because its attachment-local record is INCOMPLETE.

Extraction prompt/schema/processing/validator, quantitative engine, and targeted record fingerprint revisions are unchanged. Old generic-gap proofs stay readable and can enter the frozen retry snapshot. If the current classifier recognises their gap as local, the existing SOURCE_GAP_BINDING_MISMATCH continues to block the stored aggregate until a fresh extraction produces a consistent record; no historical record is rewritten. PPS pipeline identity includes selected attempt IDs, so fresh extractions refresh its calculations. Pipeline version advances from 0.6.5 to 0.6.6 to refresh the older supported non-PPS path whose identical source otherwise reused stale PARTIAL state after gap reclassification. This pipeline cache change does not itself call the extraction provider.

Synthetic regressions cover generic-gap retries, blank/format-only/malformed/benign exclusions, valid AVAILABLE/NO_TABLE/NOT_APPLICABLE preservation, narrow wording and mixed-subject negatives, missing/incomplete/valid/form/self sibling supply, current and exact predecessor records crossing the old generic/new local read boundary, unchanged old payloads, repeated continuations with a new local/generic/REVIEW outcome, and non-PPS pipeline cache refresh. Existing provider call ceilings, cooldowns, and quote/schema correction paths are unchanged. Production source text and company records are not test fixtures. Operational deployment and campaign outcomes require separate verification.
