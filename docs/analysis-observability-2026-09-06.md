# Analysis recovery and observability, 2026-09-06

The operator quantitative panel now reads every stored-notice page and reports the current OPEN scope separately. It counts attachment audit/acceptance, complete manifests, current eligibility, validated quantitative candidates, activation, score status, and failed diagnostic reads. Unattempted notices and failed reads are explicit; neither is counted as a successful score. Reads occur over a stated time interval, not an atomic database snapshot. No private facts or raw source payloads are included.

After reviewing a current incomplete quantitative profile, a PIN-authenticated operator can explicitly retry its reviewed attachments. The existing immutable generation boundary prevents repeated paid extraction during continuation. Loading the quantitative result also refreshes the ordinary analysis action label.

The ANY continuation selector prefers an idle compatible parent over another execution's leased parent. DAILY priority remains among equally available parents, and exact request-token replay still wins. Notice-level claims, transaction locks, deadlines and orphan recovery remain authoritative.

The attachment count cap is now the ten-file manifest bound. The existing wall-clock budget still requires enough time for a complete worst-case attachment unit before starting another. Fast attachments can complete in one request; slow ones still resume without duplicating saved siblings.

Extraction prompt 0.5.4 requires each recognition-condition literal and quote to contain the same complete source clause, including punctuation. Deliberately excluded qualitative criteria are described in the summary, while actual missing/unreadable source stays explicit. Corrective prompt 0.6.1 also permits the full exact clause within the existing 500-character anchor schema instead of mandating an 80-character truncation. No validator, source proof, company-evidence requirement, or scoring rule is weakened.

The prompt version change requires fresh current-manifest analysis under the existing version-binding contract. Older extraction/evaluation versions remain audit history. Production reanalysis and final coverage statistics must be verified after deployment; CI alone does not prove that work complete.
