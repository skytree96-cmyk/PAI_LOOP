# HWPX 문단 텍스트 추출

표를 담은 부모 `p`와 실제 셀의 `p`에서 모든 하위 `t`를 각각 수집하면 같은
셀 내용이 중복되고 표 뒤 문구도 셀보다 먼저 배치된다. 추출기는 문자열 중복
제거 대신 XML 소유 관계로 이를 방지한다.

- 명시적 iterator stack으로 XML을 순회한다. Python 재귀나 중첩 `itertext()`를
  사용하지 않으며, 텍스트를 출력하는 순회에서 각 text/tail을 한 번만 처리한다.
- 각 조각은 가장 가까운 `p`에 귀속한다. 중첩 문단의 실제 내용이 시작되면
  부모의 앞부분을 출력하고, 셀 뒤 부모 문구는 원래 순서에서 이어 출력한다.
  따라서 표를 사이에 둔 부모 문단은 순서를 유지하는 여러 출력 구간이 될 수 있다.
- 서로 다른 셀·문단의 동일 문구는 모두 유지한다. 문구 비교로 합치지 않는다.
- 자신 또는 중첩 문단에 `t`가 있는 문단은 원래 규칙대로 `t` 안의 text/tail만
  수집한다. `shapeComment`·필드 parameters 같은 비본문 메타데이터와 run 사이
  XML 들여쓰기를 제외하며, run 텍스트 사이에 새 공백을 넣지 않는다.
- `t` 자손이 전혀 없는 문단에만 기존 legacy 직접 텍스트·inline tail 처리를
  적용한다. 직접 문구와 중첩 `t`를 섞은 부모의 비`t` 문구 보존은 이번 범위에서
  제외한다. 정상 HWPX 부모의 표 전후 `t` 본문은 그대로 보존한다.
- NFC 정규화, 구간 안 공백 축약·양 끝 제거, 빈 문단 생략은 유지한다. 비어 있는
  중첩 문단만으로 부모 텍스트에 새 줄을 만들지 않는다.
- 기존 ZIP 엔트리·압축 해제 크기·경로·암호화·활성 콘텐츠·내장 첨부·외부 관계·
  XML 오류 검사를 그대로 거친다. 최종 추출 글자 수 제한도 유지한다.

이 수정은 회사 규칙, 정량 배점·비교연산자, 인용 검증, 엔진 버전을 바꾸지 않는다.
추출·처리 계약 버전과 `PPS_PROCESSING_VERSION`도 유지한다. 변경은 새로 실행되는
텍스트 추출에 적용되며 기존 저장 인용과 검증 기록을 자동 갱신하지 않는다.
배포만으로 기존 정량 미완료 공고가 복구되거나 만점·근거 불일치가 해소되는 것은 아니다.
향후 같은 문서를 다시
추출하면 구조 중복이 제거되어 텍스트와 그 해시가 달라질 수 있으므로 기존 기록의
자동 재사용·재처리 성공을 이 수정만으로 보장하지 않는다.

검증에는 합성 XML/ZIP만 사용한다. 중첩 표, 부모 앞뒤 문구, 같은 내용의 별도 셀,
run 분할·NFC, legacy text/tail, 비본문 메타데이터 제외, 빈 문단, 깊은 트리와
기존 보안 제한을 확인한다.
실제 원문·공고 식별자·운영 결과는 소스·테스트·이 문서에 포함하지 않는다.
