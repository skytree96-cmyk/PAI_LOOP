# n8n 수동 배포 운영 기준 — 2026-09-08

`.github/workflows/deploy-n8n.yml`은 `workflow_dispatch`만 지원한다.
소스의 `main` push/merge는 n8n workflow 갱신·게시를 시작하지 않는다.
이 변경은 GitHub 배포 자동화에만 적용한다. W10–W13 내부 스케줄·연결,
`manifest.json`, credential 보존 규칙, GitHub 권한 및 Render 설정은 바꾸지 않는다.

## 현재 운영 순서

사용자가 지정한 현재 n8n/Render 운영 경로는 로그인된 내부 브라우저다.
운영 변경을 수행할 때 다음 순서로 실제 상태를 확인한다.

1. Render에서 소비자 API의 대상 버전이 Live인지 확인한다. GitHub CI 성공이나
   merge만으로 배포 완료로 판단하지 않는다.
2. n8n에서 W13 변경을 적용하고 저장·게시된 버전 및 성공/안전 오류 응답 계약을
   확인한다. 기존 노드 ID와 credential 연결을 보존한다. 모델 호출이 필요한
   검증은 별도 승인된 범위에서만 수행한다.
3. W13 검증을 마친 뒤, 일시 중지했던 W11을 재개하고 실제 활성 상태를 확인한다.
   W10·W12 실행/재시도나 새 분석 캠페인은 이 배포 절차만으로 시작하지 않는다.

배포 전에 현재 실행 및 저장되지 않은 UI 편집을 확인한다. 이 소스 변경은 이미
시작됐거나 대기 중인 GitHub 배포를 취소하지 않으며, 운영에서 아무 workflow도
자동으로 중지·재개하지 않는다. 이전 runbook의 자동 push 배포 설명보다 이 문서의
진입점 및 순서가 우선하며, 개별 workflow의 검증 계약은 그대로 적용한다.

## 유지한 수동 GitHub 진입점

`workflow_dispatch`는 기존 검증 뒤 배포 스크립트를 실행하여 실제 n8n을
생성/갱신·게시할 수 있는 경로다. 브라우저 전용 운영을 대신하는 무해한 검증 버튼이
아니다. 현재 정책에서는 실행하지 않으며, 향후 사용에는 해당 운영 경로에 대한
명시적 승인이 필요하다. 기존 secrets, 권한, 동시 실행 제한, manifest 게시
허용 목록은 유지한다.

자동 배포가 없어졌으므로 소스와 운영 버전이 달라질 수 있다. 운영 담당자는 적용한
커밋과 실제 게시 상태를 확인해야 한다. n8n 내부 Schedule Trigger는 이번 변경과
독립적이므로 기존 활성 workflow의 예약 실행은 계속될 수 있다.
