# 공고 첫 표시와 근거 화면 개선

## 변경 범위

- 로그인 세션 확인은 유지한다. 최초 공고 요청은 200건에서 24건으로 줄이고, 첫 응답을 즉시 표시한 뒤 나머지를 200건씩 순차 조회한다. 24건 미만인 경우에도 런타임 설정 조회를 기다리지 않고 목록을 표시한다.
- 페이지를 이어서 가져오는 동안 검색어·부서 조건을 최초 요청 기준으로 고정한다. 전체 목록과 전역 집계를 구분하는 기존 부분 로딩 안내를 유지한다.
- 부분 목록을 표시할 때는 화면 내 공고의 자동 정량 조회를 시작하지 않는다. 전체 목록을 받은 뒤 자동 조회를 시작하여 최초 목록 요청과 부하가 겹치는 것을 줄인다. 사용자가 누른 점수 확인은 기존처럼 동작한다.
- 상세 열의 버튼을 간격이 있는 세로 배치로 묶고, 열 안에서 줄바꿈되게 한다. 갱신 버튼은 `점수 갱신`으로 줄인다. 전체 상세 보기·결과 입력의 동작은 유지한다.
- 정량 상세의 빈 근거 안내를 `산출 근거`와 `확인 필요 사항`으로 교체한다. 기존 공개 응답의 원문 검증 상태·항목 수·미확정 사유만 사용한다. 내부 사실값·원문·증빙을 새로 공개하지 않는다.
- 리스크가 미산정이어도 자격·수행·경쟁·수익성·운영·문서의 확인할 내용을 보여준다. 안내는 실제 공고에서 발견된 위험이나 증빙이 아니다. 값이 없으면 계속 `미확인`이며, 산정 보류를 0점으로 바꾸지 않는다.

## 속도 개선의 범위

첫 응답에 포함되는 공고 수는 88% 줄지만 실제 지연이 같은 비율로 줄어드는 것은 아니다. 서버의 전체 후보 순위 계산·DB 연결·인증·네트워크 시간은 여전히 발생한다. 최초 24건 표시 시간과 전체 목록 완료 시간은 구분해서 측정해야 한다. 큰 목록에서는 페이지 요청이 한 번 더 필요할 수 있다.

실서비스에서는 로그인 완료 → 첫 공고 표시, 전체 목록 완료, `/notices` 응답 시간과 `Server-Timing`을 같은 계정·필터·공고 수 조건에서 비교한다. 서버 기동 지연이나 전체 후보 순위 계산이 대부분이면 별도의 서버 개선이 필요하다. 이 변경에는 운영 DB 수정, 외부 분석 호출, 배포 설정 변경이 없다.

## 검증

- 최초 24건, 후속 200건, 1,001건 목록의 누락·중복 없음, 짧은 목록의 즉시 표시, 조회 중 필터 고정에 대한 동작 테스트.
- 정량 근거의 공개 필드 사용·HTML 이스케이프·미확인 상태, 여섯 리스크 확인 항목과 실제 0점/미확인 구분 테스트.
- 합성 데이터를 사용한 Edge 헤드리스 확인: 390, 768, 1280, 1440, 1920px에서 페이지 전체 가로 넘침 없음, 상세 버튼이 셀 내부에 있고 문구 잘림 없음. 좁은 화면의 표는 기존 가로 스크롤을 유지한다.
- 실서비스 로그인 시간과 실제 운영 데이터의 화면은 별도 확인 대상이다.
