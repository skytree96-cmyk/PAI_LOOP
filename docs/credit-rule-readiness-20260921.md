# Source-bound credit rule readiness

A verified credit table can still fail to compile when extraction omitted its
unit. Separately, a declaration that an absent appendix contains qualitative
evaluation criteria can withhold the entire quantitative profile and prevent
that table from supplying a notice's local table gap.

The credit compiler now accepts a **null** unit only for a CREDIT_RATING
CASE_TABLE with the exact `company.credit_rating` evidence key. Every categorical
row must match its own source quote and award, and the existing credit compiler
must prove a complete, nonoverlapping rating domain. Numeric operands, explicit
incompatible/empty units, other metrics, mixed scoring shapes and missing rows
remain blocked. The canonical engine unit is RATING; stored extraction values,
source anchors and awarded scores are not rewritten.

The aggregate profile can resolve an existing generic gap only when all its
current declarations are already quantitatively irrelevant or match the complete
qualitative-appendix statement grammar. Additional quantitative defects or
unreadability do not match. The original record fingerprint, extraction contract,
manifest/document binding and source-gap agreement are checked **before** this
scope projection. The stored validator classification and fingerprint revision
remain unchanged. No checksum is regenerated to make an old record pass.

Such a record can supply a sibling table only when it has a sufficiently verified
AVAILABLE table and no remaining hard issue. Exact filename role, named sibling,
distinct attachment and all other table/activation gates still apply. The
original gap remains in extraction history; the aggregate quantitative view only
narrows its effect.

This does not register company facts, assert procurement-system verification,
bind certificates or persist scores. After deployment, read the current credit
binding context. Before applying a registered certificate, verify the notice's
issuer, rating instrument, reference date and latest-rating requirements,
including procurement-system lookup when required. Certificate validity alone
does not establish those conditions.

Validation includes synthetic source-to-compiler-to-score cases, preservation of
persisted records, sibling resolution, wrong units, incomplete/overlapping rows,
foreign anchors, changed source gaps, fingerprint/manifest/document mismatches,
and independent quantitative defects. No private certificate or live source
document is included in this repository.
