# 실적 집계가 막혀 있던 두 지점 — 2026-09-23

운영 읽기 전용 조회로 원인을 좁혔다. 모든 수치는 실측이다.

## 1. 발주처 공공부문 판정

실적 인정조건이 공공부문 발주를 요구할 때, 발주처를 공공으로도 민간으로도 판정하지
못하면 계산을 멈춘다. 멈춤 자체는 옳다 — 모르는 것을 공공으로 간주하면 점수가
부풀려진다. 그러나 이름만 봐도 설립 근거가 드러나는 기관까지 멈추고 있었다.

저장된 실적 1,181건 중 **695건**이 발주처 판정 불가로 집계를 막았다. 걸린 이름은
`한국문화예술교육진흥원`, `아동권리보장원`, `국방기술품질원`, `청암대학교 산학협력단`,
`국토교통부` 같은 것들이었다. 분류 정규식에 `진흥원`·`보장원`·`품질원`·`산학협력단`이
없었고, 지자체 접두사 목록에는 개칭 전 표기(`전라북도`·`강원도`·`제주도`)가 빠져 있었다.

### 판정 순서

1. 민간 표기(`주식회사`·`㈜` 등) → 민간
2. 레지스트리의 운영자 민간 판정 → 민간
3. 레지스트리의 공공 → 공공
4. 지자체 접두사와 기존 일반 패턴 → 공공
5. 법정 기관형태(`공단`·`진흥원`·`보장원`·`평가원`·`개발원`·`기술원`·`품질원`·
   `정보원`·`산학협력단`) → 공공
6. 그 외 → **모름**(계산 중단)

`공사`·`대학`·`연구소`·`교육원`·`연수원`·`박물관`·`위원회`는 민간도 같은 말을 쓰므로
형태로 판정하지 않는다. `한빛공사`는 공기업일 수도 건설업체일 수도 있고, 부·처·청은
`발주처`·`사업본부` 같은 일반 명사와 글자가 겹친다. 그런 이름은 레지스트리에 둔다.

### 레지스트리

`src/pai_loop/data/public_agency_registry.json`

- `observed_agencies` 769종 — 나라장터 공고·낙찰 이력에 발주기관으로 나타난 이름.
  추정이 아니라 공공 조달 발주 주체였다는 관측 증거다.
- `operator_reviewed` 154종 — 관측 근거가 없어 운영자가 개별 확인한 기관. 공공 152,
  민간 2(케이티, POSCO홀딩스). 각 항목에 판정과 이유를 남긴다.

민간 판정을 '모름'으로 두지 않는 이유가 있다. 모름은 계산을 멈추므로, 민간이라고
아는 발주처 하나가 공고 전체의 실적 집계를 막는다.

### 효과

부산광역시교육청 공고에서 판정 불가가 **508건에서 12건**으로 줄었다. 정량 항목을 내는
공고가 18건에서 20건이 되었고, 인증서 바인딩을 가정한 확정 점수 합계는 158점에서
**178점**으로 늘었다(열린 공고 기준 98 → 118점).

## 2. 워크북 계약기간 표기

발주처를 고친 뒤에도 집계는 열리지 않았다. 다음 관문은 실적 레코드의 상태였다.

저장된 1,181건 중 **157건이 DRAFT**였고, 사설 워크북에서 온 미해소 행은 하나만 남아도
전체 집계를 멈춘다. 검증된 부분집합이 잘못된 정확값으로 둔갑하는 것을 막는 설계다.

원인은 워크북 계약기간 칸의 표기였다. 1,182행 중 154행이 정확한 구간을 주지 못했다.

| 형태 | 예 |
| --- | --- |
| 엑셀 날짜 시리얼·compact 날짜 | `45701`, `20231231` |
| 기간 일수 | `261일`, `계약체결후 266 일` |
| 연·월만 | `2021.12~2022.8`, `23.12~24.01` |
| 줄바꿈·연도 자릿수 | `2022121\n9`, `20222.05.23`, `202512.15` |

### 표기 복구와 기간 추론

`repair_period_text` 는 표기 흔들림만 되돌린다. 숫자 한가운데 끊긴 줄바꿈은 지우고,
두 날짜 사이를 끊은 줄바꿈은 구분자로 되살리며, 연도에 붙은 잉여 숫자와 빠진 구분점을
교정한다. 날짜를 만들어내지는 않는다.

`infer_period` 는 정확한 구간이 없을 때 계약일을 기준으로 기간을 추론한다.

- 연·월 범위 → 시작 월 1일부터 종료 월 말일까지
- 기간 일수 → 계약일부터 그 일수만큼 (1~3650일)
- 날짜 하나 → 계약일부터 그 날짜까지. 계약기간 칸에 날짜를 하나만 적었다면 종료일이다

추론한 행에는 `INFERRED_PERIOD_<근거>` 를 남겨 무엇을 채웠는지 기록한다. 날짜가 둘
이상 적힌 칸은 구간이 잘못된 것이지 단일 날짜가 아니므로 추론하지 않는다. 계약일보다
이른 날짜, 값 없는 칸, `1년` 같은 불명확한 표기도 채우지 않는다.

실제 워크북에서 **128행이 복구**되어 VALIDATED 가 1,024건에서 1,152건이 된다.

### 미해소 행 처리

기본값은 그대로 fail-closed 다. 추론하지 못한 29행은 DRAFT 로 남아 집계를 멈춘다.

`--archive-unresolved` 를 명시하면 그 행을 `ARCHIVED` 로 내리고
`ARCHIVED_UNRESOLVED_BY_OPERATOR` 를 남긴다. 미해소 행 하나가 전체 집계를 멈추는 것을
운영자가 감수하고 제외하기로 한 경우에만 쓴다. 버린 사실과 원래 사유가 함께 남는다.

## 남은 것

이 변경은 임포터와 판정 규칙만 바꾼다. 저장된 실적은 그대로다. 복구된 128행을
반영하려면 워크북 재임포트가 필요하고, 그것은 별도 승인 대상이다.

부산 공고는 재임포트 뒤 실적 금액 6점·건수 4점이 열릴 것으로 보인다. 매칭된 실적이
400억 원·195건으로 원문 최상위 구간(2억 원·5건)을 크게 넘기 때문이다. 다만 그것은
재임포트 후 실측으로 확인해야 한다.
