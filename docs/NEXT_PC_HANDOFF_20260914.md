## 보존한 변경과 미완료 부분

1. 기존 작업: 공고 전체 사유와 항목별 사유를 분리하는 부분 활성, offline replay의 funnel·strict golden 검증.
2. 이번 작업: 실적증명 발급기관/발주처 분리, 서비스 OR+공통조건 AND 보존, 고정기간·연간 금액·참가자 수·하도급 승인 등 미증명 조건의 검토 유지, 직접 서비스명/VAT/공동계약 지분 처리.
3. 이전 해석의 실적 사실이 새 검토 결과를 덮어쓰지 않도록 candidate binding에 현재 인정조건 의미를 포함. 신용·재무 binding은 유지. 엔진 `1.8.5`.
4. 순수 참조 모듈: 같은 첨부의 정확한 문자 위치·SHA·소유권에서 행→실적 서식→증명서만 연결. 중복/불완전 중복/부정/예시/외부 첨부/조건 절삭 차단.
5. **참조 모듈은 운영 QRE에 연결되지 않았다.** 실제 native 사례의 실적 행 영역이 EOF까지 열려 표 종료가 입증되지 않았고, 긴 서식은 기존 4줄 검색 한도를 넘는다. QRE 밖영역 허용이나 record fingerprint 변경은 하지 않았다. PDF 평탄화 표제도 연결 실패다.

단순 참조 연결 진단 성공, 원문 전체 검증 성공, 회사 입력 확정, 실제 총점 발행을 서로 바꿔 부르지 말 것.

## 2. 멘토에게 질문할 내용

우리는 공고 원문의 규칙과 회사의 실적·신용·재무 자료로 정량점수를 계산하려고 한다. 계산 엔진의 조건부 검증은 되지만 실제 저장 입력에서는 원문 규칙의 범위·근거와 회사 증빙 연결이 불완전하다. 다음 제품 결정을 상담한다.

1. 초기 제품은 '확인된 항목 소계 + 미확정 배점'을 먼저 보여주는 것이 적절한가? 확인 불가 실적을 제외한 보수적 추정과 최종 확정 점수를 UI에서 어떻게 구분할 것인가?
2. 증빙이 없어 제외한 실적과 원문상 미제출/0건의 점수는 다를 수 있다. 보수 계산의 공식 정책을 어떻게 정하고 사용자 승인을 받을 것인가?
3. 계약별 연간 금액, 참가자 수, VAT, 공동계약 지분, 승인 하도급, 증명 발급기관을 누가 어떤 단위로 검증·관리할 것인가? 실적 원장의 최소 추가 필드는 무엇인가?
4. 배점표가 없거나 서식·문장·다른 첨부에 규칙이 흩어진 경우, 사람이 검증한 규칙을 먼저 입력하고 자동화는 뒤따르게 하는 MVP를 수용할 수 있는가? 사람 입력에도 필요한 원문/배점/버전 증명 수준은 어디까지인가?
5. 교육·연수·컨설팅 사업만 대상으로 좁힌 10~20건의 항목별 golden을 먼저 만들고 평가할 것인가? 오산, 과대 점수, 미확정 비율, 비용을 어떤 순서로 목표화할 것인가?

이미 제외 요청한 검색 키워드: 위탁 운영, 사업기획, 회원유치, 전사 브랜딩. 이 문서는 실제 운영 반영 여부를 새로 확인한 기록이 아니다.
