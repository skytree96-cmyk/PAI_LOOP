## 작업 원칙

이 조사에서 반복해서 확인한 것이다. 지켜주면 좋겠다.

1. **만들기 전에 측정해라.** 검증기를 한 줄씩 고칠 때마다 한 자릿수만 열렸다.
   한 평가항목에 차단 사유가 4~10겹으로 쌓여 있다. 무엇이 몇 개를 막고 있는지
   DB 에서 먼저 세고, 그 수치가 작으면 만들지 마라.

2. **DB 는 읽기 전용으로 접근해라.** 쓰기는 사람 승인 사항이다.
   (scratchpad/db_url.txt 에 External Database URL, Desktop/PAI/secrets.txt 에
   PAI_LOOP_API_KEY 와 ANTHROPIC_API_KEY 가 있다. 값을 출력하지 마라.)

3. **비용이 드는 일은 규모를 먼저 알리고 승인받아라.** 첨부 1개당 약 $0.108 이다.

4. **기존 테스트가 무언가를 금지하고 있으면 이유가 있다.** 이 조사에서 두 번,
   금지 사례를 풀려다 회귀를 냈다. 금지 목록의 주석을 읽고, 그 사례가 왜 위험한지
   이해한 뒤에 바꿔라. 바꿀 때는 그 사례가 다른 근거로 여전히 막히는지 확인해라.

5. **측정이 오염되지 않았는지 의심해라.** 이 조사에서 세 번 오염된 수치를 냈다.
   비교값을 배점으로, 신용등급의 0 을 숫자로, 추출기의 인용 습관을 원문 표의
   열 순서로 잘못 셌다. 표본 몇 개를 눈으로 확인하고 나서 수치를 믿어라.

## 참고: 이 조사에서 만든 측정 스크립트

전부 읽기 전용이고 scratchpad 에 있다. 재사용하면 같은 수치를 다시 낼 수 있다.

| 스크립트 | 무엇을 재나 |
|---|---|
| `real_compile.py` | 케이스표 후보를 실제 컴파일 함수에 넣어 관문별 탈락 집계 |
| `award_strict.py` | 배점이 조건 바깥에서 증명되는지 (오염 없이) |
| `leading_award.py` | 배점이 앞에 오는 행이 얼마나 되나 |
| `uniform_order.py` | 배점-먼저가 항목 단위로 일관된가 |
| `unit_census.py` | 조건이 못 읽는 수량 단위 |
| `attachment_slot.py` | 배점표가 몇 번째 첨부·어떤 종류에 있나 |
| `diagnose_run.py` | 백필 실행이 왜 표를 못 냈는지 (저장 데이터만으로) |
| `budget_cost.py` | 첨부 단가와 시간 예산의 관계 |
| `drive_backfill.py` | 예약 → 청크별 분석 → 종결 (W11 과 같은 일) |
