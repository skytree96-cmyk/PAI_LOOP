# PAI_LOOP 공개 데이터 등록부 v0.3.0

기준일: 2026-08-17  
목적: 공모전 공개 웹과 향후 전사 온라인 서비스가 사용하는 데이터의 공개
범위와 기준 시스템을 명확히 한다. v0.1.0 등록부는 변경하지 않고 이 문서로
온라인 공개 데이터 정책을 갱신한다.

## 공개 가능한 버전 자산

| 자산 | 공개 범위 | 제외 범위 | 사용 방식 |
| --- | --- | --- | --- |
| 실제 인천 조달공고 파생 seed | 공고 식별정보, 기관·기간, 정제 요구조건 23건, 근거 앵커 26건, 문서/seed digest | 첨부 원문, provider 응답 ID, 사용자 결정, 회사 내부 값 | GitHub/wheel의 불변 seed를 PostgreSQL에 멱등 적재 |
| 회사 실적 파생 seed | 사업명, 정제 개요, 발주기관, 계약일·연도·금액, 키워드, 사업부 | 계약번호, 원본 행·경로, 주소, 담당자·전화·이메일, 직접식별자 | GitHub/wheel에서 검색 가능한 읽기 전용 데이터 |
| 회사 공개 자격 프로필 | 비영리·입찰등록 등 공개 가능 facts, 증빙 파일명·SHA-256·유효 메타데이터, 일반 제출 역량 | 증명서 본문, 등록번호, 주소, 개인 이름·연락처 | 요구조건 정책 엔진의 공개 비교 입력 |
| 부서 키워드 프로필 | 전사 기본 `교육·컨설팅`, 24개 부서/센터의 사업 키워드와 지역 축 | 조직도 인명, 연락처, 개인별 평가정보 | 검색 주체별 공고 우선순위와 설명 근거 |
| 합성 회귀 fixture | `SYN-` 식별자의 PASS/REVIEW/FAIL 사례 | 실제 회사·개인정보 | 테스트와 장애 대비 replay 전용 |

모든 공개 seed는 고정 allowlist, 버전과 digest를 검사한다. 공개 실적의 자유
서술은 전화·이메일·주소·식별번호뿐 아니라 `담당자/PM/책임자/강사 + 이름`
형태도 seed 생성 단계에서 마스킹한다. 프런트엔드는 이를 다시 마스킹하는
방어 계층을 둔다.

## 비공개·로컬 전용 원천

- 원본 기획안, Excel, PDF/HWP/HWPX/PPTX와 추출 전체 텍스트
- 증명서 본문, 등록번호, 주소, 개인 이름·연락처
- private staging DB, 원본 행 키, 내부 메모, 점수 확정 전 후보 값
- 사용자 결정, 검토 의견, 감사로그와 API/provider 원본 응답
- `secrets.txt`, `.env`, API key, DB URL, Teams webhook

이 자료는 공개 저장소·컨테이너 build context·브라우저 응답에 포함하지 않는다.
로컬 검수는 공개 자산의 재생성 및 회귀검사일 뿐 운영 데이터 원천이 아니다.

## 온라인 기준 시스템

- GitHub: 코드, 규칙, 공개 키워드, 공개-safe 불변 seed와 재현 도구
- 관리형 PostgreSQL: 공고·분석·검토 상태·사용자 결정·감사 등 변경 데이터
- 비공개 객체 저장소(후속): 허용된 첨부와 추출 원문, 보존·삭제 정책 적용
- 배포 플랫폼/n8n credential store: 외부 API 및 서버 간 자격증명

공모전 공개 화면은 `PAI_LOOP_PUBLIC_READ_ONLY=true`의 명시적 GET 허용 목록만
익명 제공한다. 전사 배포에서는 이를 Entra SSO/RBAC로 교체하고 부서·역할별
조회/결정 권한을 서버에서 검사한다.

## 갱신 절차

1. 승인된 원천을 read-only로 읽고 새 버전 seed를 생성한다.
2. allowlist, digest, 직접식별자·secret·로컬 경로 검사를 통과한다.
3. 실제 API/UI 회귀검사에서 정책 분류와 공개 응답을 확인한다.
4. GitHub Pull Request와 CI 검토 후에만 온라인 DB에 멱등 적재한다.
5. 운영 중 수정·결정은 PostgreSQL에 기록하며 seed 파일에 역기록하지 않는다.
