# 정량 항목 단위 스키마 격리 (2026-10-02)

## 문제
모델 출력의 정량평가 항목 하나가 고정 스키마(예: `CASE_NUMERIC_SHAPE_INVALID`)를 통과하지 못하면
첨부 응답 전체가 `SCHEMA_VALIDATION_ERROR`로 버려졌다. 같은 응답의 정상 배점표와 참가자격 요건도 함께 사라졌다.
10/2 대동세무고 제안요청서는 인원수와 학위·경력이 한 표에 섞인 항목 때문에 수행경험(20점)·사회적가치(10점)까지 잃었다.

## 변경
`_isolate_quantitative_schema_rows`: 스키마 오류의 위치가 **모두** `quantitative_tables[i]` 안이면,
- 오류가 `criteria[j]` 안이면 그 항목만, 표 자체 필드면 그 표만 제외하고 나머지를 다시 검증한다.
- 항목이 하나도 남지 않은 표는 제외한다.
- `missing_or_unreadable`에 고정 문구(`QUANTITATIVE_ROWS_ISOLATED_GAP`)를 더해 첨부가 완전하다고 읽히지 않게 한다.
- 제외된 항목에 점수·0점·만점을 추정하지 않는다. 값을 고쳐 받아들이지도 않는다(불리언→숫자 등).

다음 경우는 기존대로 응답 전체를 거절한다.
- 오류가 정량 표 밖(문서 유형, 요건, 요약 등)에 있거나 위치를 특정할 수 없는 경우
- 격리 후에도 검증에 실패하는 경우

## 언제 적용하나
**마지막 시도에서만** 적용한다. 그보다 앞선 시도는 기존 경로를 그대로 쓴다.
- 일반 추출(호출 2회 예산): 첫 응답은 전체 스키마 수정 재요청을 받고, 그 재요청 응답에서만 격리한다.
- 32k 단계 등 호출 1회 예산: 그 응답에서 격리한다.
- 키워드 복구: 텍스트 단계는 XML 단계로 넘기고, XML 단계에서만 격리한다.

## 한계
n8n 게이트웨이(W13)가 출력 단계에서 거절하는 `NATIVE_SCHEMA_DECODE_INVALID`는 응답이 서버에 도달하지 않으므로
이 변경으로 살릴 수 없다. 게이트웨이는 네이티브 디코딩이 강제하지 않는 `minimum`·`maximum`·`exclusiveMinimum`·
`minLength`·`maxLength`·`maxItems`를 응답 전체 단위로 다시 검사한다.
