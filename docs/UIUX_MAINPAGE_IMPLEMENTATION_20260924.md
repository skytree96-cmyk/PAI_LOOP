# 메인페이지 UIUX 구현 기록

기준: 2026-09-24, main `1ca6f53`. 별도 worktree·브랜치에서 변경했다.

사용자가 기존 톤 유지와 구현·배포를 승인했고, 비율 자동화 범위는 우리 투찰률과 낙찰자 투찰률 모두로 확인했다. 원본 피드백 문서는 검토 자료로 사용했고 저장소에 포함하지 않았다.

## 적용 범위

- 기존 파란색 메뉴, 색상·서체·모서리 토큰을 유지하면서 메뉴와 설명을 업무 용어로 정리했다.
- 저장된 전체와 진행 중 공고를 구분하고 각 집계와 같은 범위의 목록으로 연결했다. 진행 중 범위를 직접 선택하면 검색과 공유 링크에서도 유지된다. 부서는 추천 순서에 반영하며 조회 대상을 제외하지 않는다.
- 검색 버튼을 명시하고 조회 범위, 초기화되는 조건을 표시했다.
- 회사 기준 비교와 제출 전 확인을 주요 확인 사항 탭으로 옮겼다. 참가자격 설명은 펼칠 수 있으며 미충족·확인 필요·조건부 충족을 먼저 펼쳐 표시한다. 판정과 권한 규칙은 유지한다.
- 탭과 근거 이동은 상세 내부 스크롤만 사용한다. 확인된 근거 ID로 이동하며 선택된 근거에 포커스를 준다.
- 현재 공고 식별자·제목·기관·마감과 일치하는 최신 PPS 메타데이터의 허용된 계약방식만 공개 응답에 추가했다. 미확인은 수집 누락이나 충돌로 단정하지 않는다.
- 원 단위 금액에 쉼표를 표시하고 API에는 숫자로 보낸다. 소수·0·기존 지수 표기를 보존하고 잘못된 쉼표 붙여넣기를 거부한다.
- 우리 투찰률과 낙찰자 투찰률은 각각 예정가격/기초금액 및 출처를 선택해 계산한다. 서버에서 소수 넷째 자리 half-up으로 재계산하며, 두 계산의 근거와 변경 이력은 별도로 보존한다. 예산·추정가격을 기준가격으로 자동 대입하지 않는다.
- 자동 수집 원본과 담당자 검토 기록의 저장 관계를 안내하고, 결과 기록의 VALIDATED 표시를 ‘확인 완료’로 정리했다. 자동 수집 원본을 직접 수정하지 않는다.

## 검증

- 기존 대시보드·필터·권한·결과 입력 테스트 및 추가 회귀 테스트: 양쪽 비율, 독립 기준가격, 반올림, 출처 누락, 재요청 충돌, 동시 수정, 변경 이력, 공개 응답의 허용 범위.
- 실제 앱 정적 자산을 Chrome에서 실행하고 합성 API 응답으로 데스크톱·모바일 화면을 확인했다. 중복 ID·JavaScript 오류 없음, 바깥 스크롤 유지, 양쪽 비율 계산과 쉼표 없는 저장 요청 확인.
- 1,001건을 200건 단위로 끝까지 읽고 중복·누락이 없는지, 명시적 진행 중 검색 범위의 공유 링크 복원을 확인했다.
- 전체 Python coverage gate와 GitHub CI 결과는 PR에서 확인한다. PostgreSQL 동시성 검증은 CI의 임시 PostgreSQL에서 실행한다.

## 배포 기준

- 현재 운영은 Google Cloud Run `pai`, `asia-northeast1`이며 기본 주소는 `https://pai-yd7xtctmra-an.a.run.app`이다.
- 배포 전 서비스 revision `pai-00027-rtc`가 main `1ca6f53`을 실행 중임을 확인했다.
- 기존 Google Cloud Build의 GitHub main 트리거를 사용한다. CI 통과 후 main 병합, Cloud Build 완료, Cloud Run revision·commit SHA·트래픽·응답을 확인한다.
- DB 스키마 변경은 없다. 기존 JSON 감사 기록을 사용한다. 인프라 설정, n8n 워크플로, Teams manifest는 변경하지 않는다.

## 범위의 한계

- 자동 동기화 작업 자체를 새로 만들거나 기존 기록의 비율을 일괄 재계산하지 않는다. 담당자가 확인한 금액·기준가격으로 결과 입력 시 계산한다.
- 공고별 문서에 없는 계약방식이나 계산 근거를 추측해서 채우지 않는다.
- 합성 브라우저 검수에 사용한 수치와 스크린샷은 운영 데이터가 아니다.
