### 실험 비용과 한계

이번 동등성 실험은 총 18호출이었다: 검색형 100행 × 12회 + 기본형 999행 × 6회. 최초 100행씩 받는 방식은 비효율이 있었고, 이후 999행 수신이 실제 성공함을 확인했다. “환경교육 전체 수집 5회”는 그 기본형 조회 부분의 비용이며 전체 실험 비용이 아니다.

이 실험 직전 KST 당일 누적 982회에서 종료 시 1,000회가 됐고 실행·예약은 0이었다. 애플리케이션 예산에 도달해 중단했으며 이번에 제공기관 HTTP 429가 발생했다고 주장하지 않는다. 이번 동등성 실험에서 공고 API와 유료 AI 호출은 각각 0회, 업무 이력 변경은 0건이다. 호출 감사·계수 기록은 저장했다.

직전 작은 전역 건수 탐색에서는 낙찰 호출 3회(타임아웃 1회 포함)를 사용했다. 공고게시일 기준으로 2026-08-17은 5건, 08-18은 298건을 반환했으나 그때는 첫 행과 건수만 확인했으므로 전체 수집 캐시가 아니다.

## 반드시 유지할 비교 의미

1. 운영 기간은 해당 연도 포함 3개 달력연도 시작일로 계산했다. 화면의 기존 3년 표시 정책도 따로 있으므로 정확한 최근 36개월과 같다고 가정하지 않는다.
2. 운영은 공고게시일 조회이고 이번 실험은 개찰일 조회다. 3년 전체 비교 전에 같은 기간 기준으로 정렬해야 한다.
3. API의 개찰일 검색과 응답 실개찰일은 항상 일치하지 않았다. 2025-03-17 검색 결과 4,668행 중 응답 실개찰일이 같은 행은 602행이었다. 나머지를 오류라고 단정하거나 실개찰일로 다시 잘라 버리지 않는다. 조회 날짜를 UTC로 바꾼 뒤 자르지 말고 KST로 구성한다.
4. 화면의 `filter_notice_awards`는 파생 키워드 각 단어가 모두 포함되는지 본다. 수집기 `_fetch_window`는 전체 키워드 문구가 연속으로 포함되는지 검사한다. 서로 다르므로 새로 발견된 행을 수집 방식의 차이라고 바로 해석하지 않는다.
5. 수요기관은 양쪽 코드가 있으면 코드 일치 우선, 아니면 정규화한 명칭 정확 일치다. 기관명 일부일치·상위기관 추정으로 넓히지 않는다.
6. 비교 키는 공고번호·차수·입찰분류·재입찰번호다. 제목/업체명만으로 묶지 않는다. null과 0, 미조회와 조회 결과 없음은 구분한다.
7. 참가업체별 개찰 결과·평가점수는 최종낙찰 목록과 별도 API다. 최종 업체·금액의 일치가 모든 부가 점수까지 일치함을 뜻하지 않는다.

## 코드 지도와 다른 PC 준비

- `src/pai_loop/award_scope.py`: 실제 수요기관 근거 해석, 키워드 파생, 공통 표시 필터.
- `src/pai_loop/integrations/awards.py`: 최종낙찰 정규화·구간 조회·별도 개찰 결과.
- `src/pai_loop/integrations/pps.py`: HTTP 호출·응답 파싱·날짜 파싱.
- `src/pai_loop/award_automation.py`: 계획·실행·일일 예산·재시도.
- `src/pai_loop/award_automation_models.py`: 큐 상태·호출 예약 시도.
- `src/pai_loop/models.py`: `AwardHistoryItem`, `IngestionJob`, 수요기관 부가 메타데이터.
- `workflows/pai-loop-14-award-history-automation.json`: W14.
- `GET /api/v1/operations/award-refresh/status`: 보호된 상태 조회. `X-PAI-LOOP-API-KEY` 헤더는 서버에서만 주입한다.
- `POST /api/v1/operations/award-refresh/plan`, `.../run`: 상태를 바꾸거나 실제 수집하는 경로이므로 상태 확인 용도로 호출하지 않는다.

로컬 개발은 Python 3.12와 프로젝트 pyproject.toml을 따른다. GitHub 인증, PPS_API_KEY, 보호된 백엔드 접근 설정, 필요한 경우 승인된 DB/n8n 접근은 새 PC에서 안전하게 연결한다. 비밀값을 채팅·GitHub·메일에 붙이지 않는다. 실제 DB는 읽기 전용으로 기준을 확인하고, 운영 호출 감사 기록은 기존 승인된 수집 경로를 사용한다. 테스트·마이그레이션은 운영 DB에 실행하지 않는다.

### 원래 PC에만 있는 파일

다음은 `.local/`에 있고 Git에 포함되지 않는다. 새 PC에 자동으로 생긴다고 가정하면 안 된다.

- `award-economy-trial.py`, `award-economy-trial-result.json`: 공고 우선 검색 실험.
- `award-global-equivalence.py`, `award-global-equivalence.json`: 검색형 100행 페이지 실험.
- `award-global-equivalence-basic.py`, `award-global-equivalence-basic.json`: 기본형 999행 수집과 비교.
- `award-global-equivalence-report.md`: 실험 보고서.
- `award-global-volume-probe.json`: 작은 건수 탐색.
- `pps-efficiency-specs/`: 공식 참고자료에서 추출한 텍스트.
- `task-ops.mjs` 및 배포·검증 결과 파일: 당시 운영 보조 자료.

실험 스크립트는 다른 로컬 스크립트를 연쇄 import하고 원래 PC의 설정 파일에 의존한다. 상태 JSON이 이미 있으면 재실행을 막도록 되어 있어, 그대로 실행하는 것은 남은 페이지 재개가 아니다. 새 PC에서는 위 API 조건과 비교 절차로 작은 재개 도구를 만들거나, 안전하게 전달받은 캐시를 사용하되 비밀값·원본 제공기관 응답은 공개 저장소로 옮기지 않는다.

이 문서 작성 작업은 인수인계 기록의 게시와 본인 메일 발송이다. 수집 로직·워크플로·운영 배포는 변경하지 않는다.
