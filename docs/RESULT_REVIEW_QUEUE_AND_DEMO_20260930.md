# 결과 기록: 자동 반영 확인 탭과 발표용 시연 결과 (2026-09-30)

## 결과 기록 화면

`입찰 결과 → 결과 기록`(`/results`)은 들어오면 바로 목록을 불러온다. 로그인 확인은 런타임
프로필만 기다리고 전체 공고 페이지 로딩을 기다리지 않는다. 확인이 끝나기 전에 목록 새로고침을
누르면 무시하지 않고 "로그인 상태를 확인하고 있습니다"를 표시한 뒤, 확인이 끝나면 자동으로 불러온다.

목록은 **결과가 기록된 공고를 먼저** 보여준다. 기준은 조회자에게 보이는 기록이다. 부서 계정은
자기 부서 기록, 없으면 나라장터 자동 반영 기록이고, 관리자는 가장 최근 기록이다. 기록된 공고끼리는
최근 기록 순이고, 나머지는 기존처럼 마감이 늦은 순이다.

목록 위 탭:

| 탭 | 조건 |
| --- | --- |
| 전체 | 기존 조회 범위(종료 공고와 결과가 있는 공고) |
| 나라장터 자동 반영 · 확인 필요 | 부서가 없는 자동 기록(`MANUAL_UI`가 아닌 출처)이 있고, 가장 최근 자동 관측 이후 조회자 부서의 기록이 없는 공고 |

관리자에게는 어느 부서든 자동 관측 이후 기록을 남기면 확인된 것으로 본다. 같은 조건의 건수가
API `auto_review_count`, 대시보드 `result_review_count`, 사이드바 `결과 기록` 배지에 쓰인다.
확인이 필요한 자동 기록 카드는 저장된 기록 상태와 관계없이 `확인 필요`로 표시한다.
이 탭은 표시와 조회만 바꾸며 자동 반영의 검증 기준(`_workflow`)과 결과 입력 큐 판정은 그대로다.

## 발표용 시연 결과

매일 07:30 자동 반영(W10 → `/api/v1/outcome-feedback/pps/refresh`)은 2026-09-30 기준 운영 DB에
자동 기록을 한 건도 만들지 않았다. 발표에서 이 흐름을 보이기 위해
`python -m pai_loop.demo_outcome_feedback_cli`가 시연 결과를 넣고 지운다.

- 대상: 판단·결과가 전혀 없는 실제 종료 PPS 공고(취소 공고 제외). 부서 작업 큐는 바뀌지 않는다.
- 모양: 출처 `PPS_AUTO_FEEDBACK`, 부서 없음. 짝수 번째는 우리 회사 낙찰(자동 확인 완료),
  홀수 번째는 `경쟁사 A…` 낙찰·참여 미확인(확인 필요). 낙찰금액은 추정가격의 87~95%.
- 표시: `evidence_json.demo_seed.marker = "DEMO_SEED"`. 결과 카드와 상세 `입찰 결과` 탭에
  `시연` 배지와 "실제 개찰 결과가 아닙니다" 안내가 붙는다. 출처·근거는 `시연 예시 데이터`.
- 영향 범위: 결과 기록 화면, 결과 입력 큐, 대시보드 결과 집계. 참가자격·정량점수·판단에는 쓰이지 않는다.

```bash
python -m pai_loop.demo_outcome_feedback_cli plan --count 6    # 쓰기 없이 대상만 출력
python -m pai_loop.demo_outcome_feedback_cli apply --count 6   # 시연 결과 추가(이미 있으면 거부)
python -m pai_loop.demo_outcome_feedback_cli purge             # 시연 결과와 그것을 바탕으로 만든 부서 검토본 삭제
```

`--notice-key`를 반복해 대상을 직접 고를 수 있다. 이때도 판단·결과가 없는 종료 공고만 허용한다.
`PAI_LOOP_DATABASE_URL`이 필요하며, 운영에서는 서비스와 같은 이미지·Cloud SQL 연결을 쓰는
일회성 Cloud Run 작업으로 실행한다. **발표가 끝나면 `purge`를 실행한다.**
