## 실제로 수정한 오류

기존 엔진은 `OUT_OF_SCOPE` 행을 준비도 분모에서만 제외했다. 정량 총배점과 예상 상한에는 정성·가격 등의 배점을 넣어, 이미 정량 외로 분류한 항목까지 만점을 가정했다.

엔진 `1.8.2`는 이 행들을 정량 합계·하한·상한에서 제외한다. 원래 행의 배점과 미산정 사유는 보존하고 `out_of_scope_points`로 분리한다. 예를 들어 정량 40점이 확정되고 별도 정성 60점이 있으면 정량 결과는 40/40이며 별도 배점은 60이다. 20점만 확정되고 실제 정량 20점이 검토 상태이면 정량 범위는 20~40/40으로 남는다. 실제 정량의 미확인을 범위 외로 바꾸지 않는다.

혼합 평가의 최소점수가 정량 소계용인지 전체 기술평가용인지 표현되어 있지 않으므로 `meets_minimum`은 미확정으로 남긴다. 순수 정량 요청은 기존 최소점수 비교를 유지한다. 전부 정량 외이면 점수를 확정하지 않는다.

공개 스냅샷은 `OUT_OF_SCOPE` 상태를 허용하면서도 합계 검사와 복원에서 처리하지 못했다. 혼합 결과의 저장 검증 실패를 고치고, 공개 응답에서도 정량 합계와 별도 배점을 검증·복원한다. 제외 합계 불일치나 제외 항목에 임의로 부여한 점수는 거절한다. 공개 행에는 회사 사실과 자유 원문을 노출하지 않는다.

화면도 정량 외 행을 별도로 배치하고, 그 범위를 예상 정량점수로 표시하지 않는다. 미확정 사유는 실제 정량 항목에서 찾는다. 전부 정량 외일 때는 `0 / 0` 대신 미산정으로 표시한다. PC·모바일에서 확인했으며 긴 상태 문구의 모바일 넘침도 수정했다. JS/CSS 캐시는 `20260913-quantitative-v4`로 맞췄다.

이 변경은 **기존 분류 결과의 합산·저장·표시 오류를 수정**한다. 분류 정규식이나 metric registry, 추출 계약·fingerprint의 허용 범위를 넓히지 않았다.

검증: 점수·공개 저장복원·분석 pipeline·원문 누락 보호·CASE 배점 근거·프론트 관련 11개 테스트 파일 **365개 통과**. 전부 범위 밖인 상태의 문구를 마지막으로 정리한 뒤 해당 프론트 회귀를 재검증했다. 전체 CI/coverage 실행은 아니다. 실제 CSS/JS를 사용한 로컬 Chrome의 PC 1440px·모바일 390px 합성 예제에서 화면 넘침·표시를 확인했고, 브라우저 외부 요청은 모두 로컬에서 처리했다.

## 다음 원문 수정의 경계

현재 추출 후보에는 부모 평가범위가 없고 원문 누락도 문자열 목록이다. 그래서 정성 항목의 오류가 표 전체 미완료로 전파될 수 있다. 다음 수정은 원문에 근거한 부모 범위와 누락의 소속을 보존해야 한다.

- 홍천 교육: 정량 20·정성 60·가격 20 중 정성 4항목을 분리할 필요가 있다. 정량 4항목의 비교기호·배점·인용 오류는 별도로 고쳐야 한다.
- RISE 연수: 과업지시서 10~11쪽에 신용 정량 10점이 있고 유사사업 실적은 정성이다. 파일명이나 실적이라는 단어만으로 범위를 판단하지 않는다.
- 구내식당: 제안평가의 정량 10·정성 90과 별도 설문 100은 다른 단계다. 같은 항목명이 반복되므로 단계와 80%/20% 가중치를 보존해야 한다. 객관적 준수와 주관적 제안이 혼재한 가감점 2행은 계속 검토한다.

범위 증명에는 동일 첨부의 부모 표제, 해당 행이 속한 원문 경계, 단계별 원문 소계가 필요하다. 정성·가격 전용 누락이라고 증명된 경우에만 정량 차단과 분리하고, 혼합·미확정 누락은 계속 차단해야 한다. 전체 총점에서 제외 배점을 뺀 값을 원문 정량 소계처럼 만들지 않는다. 기존 구계약을 최신 계약으로 덧씌우거나 인용·구간 검증을 해제하는 방식은 사용하지 않는다.

원문 경로·해시·25행 소속·누락 84문구의 검토 상태는 private `scope_candidate_audit.private.json`에, 단계별 비교는 `scope_totals_offline_comparison.private.json`에 보존했다. 누락 84문구 중 원문 확정 판정은 4개이며 나머지는 선별 결과다. 전수 원문 검증 완료로 세지 않는다.
