# 근거 기반 정량점수 추정 v0.3.0

## 목적과 경계

PAI_LOOP의 정량점수는 제안요청서의 배점표와 공개 가능한 회사 증빙을 결정론적으로 연결해 `확정점수` 또는 `잠정 범위`를 제시한다. 정량 준비도는 다음 판단과 분리한다.

- 입찰 참가자격 `PASS / REVIEW / FAIL`
- 담당자의 `GO / HOLD / NO-GO`
- 발주기관이 확정하는 최종 평가점수

배점표, 배점구간 또는 회사 증빙이 없으면 0점으로 간주하거나 만점을 추측하지 않는다. `REVIEW` 또는 `UNSCORABLE`로 남기고, 원문에 명시된 조건부 최소점수만 별도 하한으로 표시한다.

## 구성

- 프로필: `src/pai_loop/data/quantitative_notice_profiles.json`
- 엔진/API: `src/pai_loop/quantitative_scoring.py`
- 조회 API: `GET /api/v1/notices/{notice_key}/quantitative-estimate`
- 화면: 공고 상세의 `정량·리스크` 탭
- 프로필 버전: `2026.08.17-v2`
- 엔진 버전: `pai-loop-quantitative-engine-1.0.0`

엔진은 OpenAI 또는 조달청 API를 호출하지 않는다. 패키지에 포함된 공개 안전 스냅샷과 공고별 규칙 프로필만 읽는다.

## 데이터 계약

각 평가항목은 아래 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `criterion_id`, `category`, `label` | 항목 식별자와 표시명 |
| `max_points` | 원문상 항목 만점 |
| `metric_key`, `unit` | 회사 데이터와 연결할 값 |
| `formula_type`, `formula`, `brackets` | `BRACKET` 또는 `BOOLEAN` 산식과 배점구간 |
| `rule_floor_points`, `floor_condition` | 회사 사실이 아닌 원문상 조건부 최소점수와 적용 전제 |
| `rule_base_points`, `base_condition` | 가감 전 기본점수와 적용 전제. 최소점수와 분리 |
| `source_anchor` | 문서명, SHA-256, PDF 페이지, 표 구역 |
| `required_evidence_keys` | 허용된 증빙 버전 또는 데이터셋 다이제스트 |

회사 사실은 `metric_key`, 값 또는 하한·상한, 증빙 키, 상태, 신뢰도, 근거 설명으로 전달한다. 증빙 키가 규칙 프로필과 다르면 점수를 적용하지 않고 `REVIEW`로 닫힌다.

## 상태와 합계

| 상태 | 의미 |
|---|---|
| `CONFIRMED` | 허용 증빙과 단일 값이 산식에 일치 |
| `ESTIMATED` | 공개 후보 데이터의 하한·상한을 배점구간에 적용한 잠정 범위 |
| `UNSCORABLE` | 산식은 있으나 필요한 회사 데이터가 없음 |
| `REVIEW` | 배점구간·원문 앵커·증빙 연결이 불완전하거나 모순됨 |

- `lower_points`: 각 항목의 보수적 하한 합계
- `upper_points`: 미확인 항목의 원문상 만점을 포함한 상한 합계
- `confirmed_points`: `CONFIRMED` 항목 점수만 합계
- `evidence_coverage_pct`: `CONFIRMED` 항목의 만점 합계 / 전체 만점
- `readiness_pct`: 하한 / 전체 만점
- `unscorable_points`: 조건부 하한을 제외하고 아직 열려 있는 점수 폭

항목별 결과가 단일 값으로 좁혀지지 않으면 `estimated_points`는 `null`이다. 합계 또한 범위로 표시해 가짜 정밀도를 만들지 않는다.

## 준비도 색상

기획안과 데이터 준비목록의 기준을 그대로 사용한다.

- `GREEN`: 하한 준비도 80% 이상이면서 검증 커버리지 80% 이상
- `YELLOW`: 하한 준비도 70~79.99% 또는 검증 커버리지 60~79.99%
- `RED`: 하한 준비도 70% 미만 또는 검증 커버리지 60% 미만
- `GRAY`: 공고별 정량평가표 또는 핵심 산식 미확보

`RED`는 자동 `NO-GO`가 아니다. 누락 증빙과 규칙을 보완할 우선순위를 뜻한다.

## 실제 공개 RFP 적용

`2025 AI 활용 역량 강화 교육 운영 용역 제안요청서.pdf`를 실제 파생 프로필로 등록했다.

- SHA-256: `53b24e9dae63328d4f692e4cbe21e7148e0f24614dedbec5c356e2adbfc84648`
- 정량표 앵커: PDF 14~16쪽, 인쇄면 25~30쪽
- 정량 총점: 20점
- 신용평가등급 6점, 전문인력 5점, 최근 3년 유사실적 3점, 사회적·약자기업 3점, 안전보건 3점

현재 공개 데이터 적용 결과는 다음과 같다.

| 항목 | 범위 | 상태 | 이유 |
|---|---:|---|---|
| 신용평가등급 | 4.2~6 | `REVIEW` | 원문상 미제출·확인불가 하한은 확인했으나 전체 등급표와 회사 유효등급 연결은 미완료 |
| 전문인력 | 3~5 | `UNSCORABLE` | 원문 배점구간은 확인했지만 공개 인력 집계가 없음 |
| 유사실적 | 1.5~3 | `ESTIMATED` | 공개 실적 후보의 0원~후보합계 범위만 사용 |
| 사회적·약자기업 | 1~3 | `REVIEW` | 기본점수는 확인했지만 세부 가점표와 회사 증빙 연결은 미완료 |
| 안전보건 | 0~3 | `REVIEW` | 가감 전 기본 2점은 확인했지만 사고 감점 시 0점까지 가능하고 회사 증빙 연결은 미완료 |

따라서 현재 화면은 **조건부 하한 9.7점~상한 20점**, 검증 커버리지 0%, `RED / REVIEW`로 표시한다. 9.7점은 회사의 확정점수가 아니라 유효한 평가대상 입찰로 접수된다는 전제 아래 원문 규정에서 도출한 조건부 하한이다. 안전보건의 기본 2점은 사고 감점 전 기준이므로 보수적 하한에는 넣지 않는다.

공개 실적 스냅샷 `2026.08.17-v3`에는 기간, 단일계약 3천만원 이상, 교육 및 AI·인공지능·데이터 키워드 조건을 기계 적용한 후보가 37건, 후보금액 합계 17,809,102,812원이다. 이 값은 인정실적이 아니다. 완료 여부, 발주기관의 유사성 인정, VAT 포함 여부, 공동수급 지분, 실적증명 원본을 확인하기 전에는 3점으로 확정하지 않는다.

## 배점표가 없는 실제 공고

인천 승진후보자 교육 공개 시드 `MANUAL-INCHON-2025-17`에는 입찰공고문 요구조건은 있지만 정량평가표와 인정 산식이 없다. 이 공고는 다음처럼 유지한다.

- `rule_source_status = MISSING`
- 총점, 하한, 상한 모두 `null`
- `GRAY / REVIEW`
- 공개 유사실적 후보 26건은 관찰 정보로만 표시

제안요청서 배점표를 확보하기 전에는 다른 공고의 20점표를 재사용하지 않는다.

## 운영 체크리스트

1. 공고 원문 SHA-256과 PDF 페이지를 먼저 고정한다.
2. 항목 만점, 구간 경계, 포함·제외 조건을 원문과 대조한다.
3. 원문에 없는 최소점수나 회사 값을 만들지 않는다.
4. 공개 실적은 후보 풀로만 사용하고 인정실적 증빙을 별도로 확인한다.
5. 데이터셋 버전 또는 SHA가 바뀌면 `required_evidence_keys`를 재검토한다.
6. 사람 이름, 연락처, 등록번호, 원문 증명서 본문을 프로필과 API에 넣지 않는다.
7. 테스트에서 확정·범위·누락·중복·배점표 미확보·실제 RFP 회귀를 모두 확인한다.
