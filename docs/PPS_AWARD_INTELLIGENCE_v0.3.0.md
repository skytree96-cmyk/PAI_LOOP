# PAI_LOOP 3년 낙찰·가격 인텔리전스 v0.3.0

## 목적과 데이터 경계

`GET /api/v1/notices/{notice_key}/award-intelligence`는 **이미 PAI_LOOP DB에 저장된 최근 3년 제목 유사 후보만** 읽는다. 이 조회는 조달청 API, OpenAI API, n8n 또는 외부 네트워크를 호출하지 않는다.

제목 유사 후보는 동일 과업·동일 평가방식의 확정 비교군이 아니다. 화면과 API의 모든 예측은 `MODEL_ESTIMATE`, 원천 사실은 `EXPLICIT_SOURCE`, 공식 산식으로 계산 가능한 값은 `DERIVED_*`, 값이 없으면 `UNAVAILABLE`로 구분한다.

## 공식 필드 정의 기준

- 조달청 나라장터 낙찰정보서비스는 최종낙찰자, 개찰순위, 복수예비가격·예비가격 정보를 제공한다. 공식 설명상 복수예비가격 15개 중 추첨된 4개로 예정가격이 정해지고, 낙찰률은 `낙찰금액 / 예정가격`이다: [조달청 나라장터 낙찰정보서비스](https://www.data.go.kr/data/15129397/openapi.do)
- 공고의 기초금액 등은 별도 입찰공고정보서비스 필드다: [조달청 나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)
- 발주기관이 나라장터에서 전체 절차를 처리하지 않은 경우 공고·개찰·낙찰 정보가 없을 수 있다는 공식 주의가 있다. 따라서 누락은 0이나 PASS로 해석하지 않는다: [조달청 계약과정통합공개서비스](https://www.data.go.kr/data/15129459/openapi.do)

PAI_LOOP는 아래 값을 절대 서로 대체하지 않는다.

| 필드 | 의미 | 허용 계산 |
|---|---|---|
| `winner_name` | 명시된 최종 낙찰자 | 다른 참가자/계약자에서 추정 금지 |
| `award_amount` | 명시된 낙찰금액 | 투찰금액으로 간주 금지 |
| `estimated_price` | 명시된 예정가격 | 공고 추정금액과 동일시 금지 |
| `submitted_bid_price` | 명시된 해당 투찰금액 | 낙찰금액으로 보간 금지 |
| `award_rate` | 명시값 또는 낙찰금액÷예정가격 | 두 입력이 모두 있을 때만 산출 |
| `submitted_bid_rate` | 투찰금액÷예정가격 | 두 입력이 모두 있을 때만 산출 |
| `technical_score` / `price_score` | 명시된 평가점수 | 낙찰 여부·금액으로 역산 금지 |

현재 저장 테이블에 예정가격·투찰금액·기술점수·가격점수가 없다면 API는 해당 필드를 `null`로 반환하고 커버리지를 0으로 표시한다. 대상 공고의 `estimated_amount`는 금액 범위의 별도 기준값 `NOTICE_ESTIMATED_AMOUNT`로만 쓰며, 조달청 예정가격과 같다고 주장하지 않는다.

## 계산 방식

### 수주 집중도

- 낙찰자가 명시된 표본만 집계한다.
- 최다 수주사, 수주 횟수·표본 내 비율, 2회 이상 반복 수주사 수를 제공한다.
- `HHI = Σ(표본 내 수주 비율 × 100)²`이다. 1,500 미만/1,500~2,500/2,500 초과를 각각 LOW/MODERATE/HIGH로 표시하되, 이는 내부 탐색 구간이며 법적 시장획정이나 전체 시장점유율이 아니다.

### 낙찰률·투찰률과 예측

- 분포: 개수, 최솟값, 25백분위, 중앙값, 평균, 75백분위, 최댓값.
- 예측: 최신 관측을 더 반영하기 위해 365일 반감기 지수 가중평균을 사용한다.
- 참고 범위: `가중평균 ± 1.5 × 가중 절대편차`, 최소 반폭 0.25%p.
- 표본 3건 미만은 `INSUFFICIENT_DATA`로 수치 예측을 내지 않는다. 3~4건 LOW, 5~7건 MEDIUM, 8건 이상 HIGH다.
- 명시적 투찰금액 표본이 부족하면 낙찰률 예측을 투찰률 예측으로 복제하지 않는다.
- 대상 기준금액이 있고 낙찰률 예측이 가능한 경우에만 `기준금액 × 예측 낙찰률`로 낙찰금액 참고 범위를 계산한다.

## 재현 가능한 검증 자료

`tests/fixtures/award_intelligence_synthetic_v1.json`은 모두 “합성”으로 표시된 테스트 전용 자료다. 실제 업체명, 담당자명, 사업자번호, 연락처, API 키가 없다. `tests/test_award_intelligence.py`는 HHI, 중앙값, 최근가중 예측, 표본부족, 필드 간 오인 방지, 외부 클라이언트 미호출을 결정론적으로 검증한다.

공개 배포에는 별도의 `PUBLIC_PROCUREMENT_DERIVED` seed를 사용한다. `src/pai_loop/data/public_award_history_seed_v1.json`은 로컬 검증 DB의 조달청 공개 낙찰 사실을 다음 절차로만 파생한다.

1. 공개 공고 키 `MANUAL-INCHON-2025-17`에 이미 연결된 저장 이력만 선택한다.
2. 공고번호·제목·발주기관·낙찰기관·참여 수·낙찰금액·낙찰률·공개 일자·제목유사도만 allowlist 한다.
3. 원문 응답, 내부 DB ID, 사업자/주민번호, 전화, 이메일, 담당자/대표자명, 사람 이름으로만 보이는 낙찰자 행을 제외한다.
4. 레코드 전체의 SHA-256과 제외 건수를 provenance에 기록하고 변조 시 fail closed 한다.
5. Render 초기 배포 hook가 기존 공개 공고를 먼저 만든 뒤 seed를 idempotent하게 가져온다. 외부 API 호출은 없다.

## 공고별 가격평가 산식

가격평가법은 모든 공고에 일반화하지 않는다. `pricing_method_profiles_v1.json`은 문서 SHA-256이 정확히 같은 경우에만 산식과 PDF 근거 위치를 반환한다.

- 현재 등록 profile의 근거: `2025 AI 활용 역량 강화 교육 운영 용역 제안요청서`, SHA-256 `53b24e9d…fc84648`, PDF 16쪽/인쇄면 30쪽.
- 가격 배점 10점, 예정가격 80% 이상/미만 구간별 산식, 일반 70% 하한, SW·지정 안전장비 80% 하한, 하한 미만 배점한도의 30% 규정을 구조화했다.
- 유효 최저가·해당 투찰가·예정가격이 모두 없으면 가격점수는 계산하지 않는다.
- 인천광역시인재개발원 공개 공고는 문서 SHA가 다르므로 이 산식을 표시하거나 적용하지 않는다.

## 사용자 해석 원칙

이 결과는 입찰 전략 회의를 위한 탐색 자료다. 낙찰, 투찰가격, 평가점수, 인정실적 또는 최종 GO/NO-GO를 확정하지 않는다. 동일 과업 여부, 공고별 낙찰자 결정방식, 예정가격 산정방식, 평가표 및 최신 원문은 담당자가 최종 확인한다.
