# 공개 회사 프로필과 요구조건 4분류

## 목적

웹 배포 환경은 개인 PC의 로컬 파일을 읽지 않는다. 공개 가능한 회사 사실은
`src/pai_loop/data/company_public_profile.json`에 버전 관리하며 API와 웹 화면은 이
프로필만 사용한다. 증명서 원문, 등록번호, 주소, 연락처, 사람 이름과 민감 식별자는
프로필에 포함하지 않는다.

공개 증빙 메타데이터는 표시용 파일명, SHA-256, 유효시작일, 최종 확인일,
유효종료일 및 마감일 재확인 정책으로 한정한다. 프로필 로더는 금지 필드와 대표적인
민감값 패턴을 발견하면 서버 시작 후 조회 단계에서 실패하도록 구성했다.

## 네 가지 분류

| 분류 | 의미 | 판정 영향 |
|---|---|---|
| `ELIGIBILITY` | 법적·등록·제재·법인 유형 등 참가 적격성 | 공개 근거와 마감일 기준으로 PASS/REVIEW |
| `ACTION_REQUIRED` | 특정 공고에서 실제로 수행해야 하는 1회성 행동 | 완료 확인 전 BLOCK |
| `CHECKLIST` | 제출·발표·서약·참석자·산출내역 등 준비 절차 | 준비 상태를 표시하되 그 자체로 적격성 REVIEW를 만들지 않음 |
| `INFORMATION` | 전자입찰, 총액 제출, 계약기간 등 계약·절차 정보 | 참고 정보이며 적격성 판정과 분리 |

인천광역시 인재개발원 예시에서는 경쟁입찰참가자격 등록, 부정당 제재 상태,
비영리법인 예외 및 유죄판결 상태를 적격성으로 처리한다. 하도급 금지, 방문 제출,
PM 발표, 참석자 제한, 서약서와 산출내역은 체크리스트로 처리하고, 전자입찰·총액
제출·계약기간은 정보로 처리한다. 제안설명회 필수 참석만 `ACTION_REQUIRED`이며
참석 기록이 확인되기 전에는 `BLOCK_UNTIL_CONFIRMED` 상태다.

## 마감일 기준 원칙

- `PASS_CURRENT`는 영구 PASS가 아니다. 해당 공고 마감일에 나라장터 또는 요구된
  최신 증빙을 다시 확인한다.
- `PASS_EXCEPTION`은 공고 원문에 비영리법인 예외가 명시된 경우에만 적용한다.
- 현재 확인 선언의 적용 종료일 이후 공고에는 자동으로 `REVIEW`를 반환한다.
- 체크리스트 준비 가능 상태는 실제 제출·서명·참석 완료를 의미하지 않는다.

## API

- `GET /api/v1/company-profile`: 저장소 기반 공개 안전 프로필
- `GET /api/v1/notices/{notice_key}/analysis/requirement-policy`: 최신 승인 추출 결과에
  4분류 정책 적용

웹 상세 화면은 두 번째 API를 사용한다. 공개 런타임에는 사내 원천 반입 또는
로컬 데이터 매칭 API가 존재하지 않는다.
